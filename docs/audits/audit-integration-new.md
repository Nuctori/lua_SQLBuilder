## 一、spec/helpers/db.lua — 三个新 adapter

### 结论：连接参数 / 结果归一化 / 错误处理基本正确，无阻断级缺陷

#### duckdb adapter — 正确（源码核对 + 渲染验证）
- `:memory:` 连接：luasql-duckdb 2.8.0 的 `env_connect` 调 `duckdb_open_ext(sourcename, ...)`，`":memory:"` 是 DuckDB C API 的合法内存库标识（db.lua:357）。
- fetch 约定：驱动 `cur_fetch` 为 `cursor:fetch(table, "a")` 签名（第 2 参必须是 table、模式串在第 3 参）——adapter 的 `cursor:fetch({}, "a")`（db.lua:296-297 区域）与之吻合；`'a'` 模式键名来自 `duckdb_column_name`（**不转小写**），与 fixtures 小写未加引号标识符一致；`SELECT COUNT(*) AS n` → 键 `n` ✓。
- `last_insert_id`（db.lua:315）：`getlastautoid` 是 mysql 专属方法，duckdb/oci8 上 pcall 兜底返回 nil——安全，且集成 spec 未调用（上轮 P1-3 潜伏项，未变）。
- 数值归一化：duckdb DOUBLE 返回 `"999.0"` 形态，`normalize_value` 的 `^%-?%d+%.%d+$` 分支已覆盖（commit 1a163ed 修复过）。

#### clickhouse adapter — 正确（端到端模拟验证，真实代码路径）
用 fake `socket.http`/`ltn12`/`cjson` 驱动真实 adapter 验证：
- URL `http://127.0.0.1:8123/?user=default&password=clickhouse`，POST + `Content-Type` header ✓
- luasocket table-form 取第 2 个返回值作状态码（db.lua:416 `local _, code`）✓；连接失败时 `http.request` 返回 `nil, err`，err 串被当作 "code" 拼进报错——**不影响测试判定，仅报错信息误导**（见 F-1）
- 非 200 时返回 body 错误文本 ✓（模拟 `Code: 62. DB::Exception...` 正确透出）
- SELECT 追加 `FORMAT JSONEachRow`（db.lua:445）✓；空 body → `{}` ✓
- `pcall(self._cjson.decode, line)` 平函数调用 ✓（commit 5d1406f 已修）；`cjson.null` 跳过 NULL 列 ✓（模拟验证：`{"profile":null}` 行 profile 键被剔除）
- `conn.close = function() end`：HTTP 无状态，合理

#### oracle adapter — 正确（luasql-oci8 源码核对）
- EZCONNECT：`env:connect("host:port/service", user, password)`（db.lua:377），`127.0.0.1:1521/FREEPDB1` 为合法 EZCONNECT 串，与 gvenzl/oracle-free 的 APP_USER/FREEPDB1 匹配。
- **fetch 'a' 键名大小写——已从 luasql-oci8 2.6.0-3 源码确认**：`copy_column_name()` 显式 `tolower()` 全部列名（`src/ls_oci8.c:160-166`），故 `rows[1].name`、`rows[1].n`、`rows[1].num` 等小写键断言成立（上轮担心的 UPPERCASE 键问题不存在）。
- `cursor:fetch({}, "a")` 签名与 oci8 驱动 `cur_fetch`（table 第 2 参、模式第 3 参）吻合。
- Oracle 侧 `COUNT(*)`/NUMBER 返回字符串，`normalize_value` 转数字 ✓。

#### 新 adapter 上的遗留（上轮已报、本次仍适用）
- **P1-1 复现**：`make_luasql_conn:query` 中 `if v ~= nil then`（db.lua:304）丢弃 NULL 列 → duckdb/oracle 上 "列 NULL" 与 "列不存在" 不可区分。当前断言未触 NULL 列，潜伏。
- **P1-2 复现**：`normalize_value`（db.lua:42）把形如 `"123"` 的文本列强转数字。当前 fixtures 无此形态，潜伏。

### 发现的问题

- **F-1 [低] db.lua:416-425 clickhouse 连接失败报错误导**：luasocket 连接失败时 `http.request` 返回 `(nil, "connection refused")`，adapter 取第 2 值当状态码，报出 `clickhouse HTTP connection refused: `。模拟验证可达；只影响诊断可读性。建议：捕获第 1 返回值，nil 时直接返回错误串。
- **F-2 [低] db.lua:400 clickhouse URL 未做 URL 编码**：`?user=%s&password=%s` 原样拼接；密码含 `&`/`@`/空格时会破坏认证。CI 密码 `clickhouse` 安全。建议 `socket.url.escape` 或显式注明约束。

## 二、spec/helpers/fixtures.lua — 新方言 schema 与种子

### 结论：DDL/种子 SQL 全部合法（六方言逐条渲染核对）

- **duckdb**：`INTEGER PRIMARY KEY` / `TEXT` / `DOUBLE` / `VARCHAR` 合法；`DROP TABLE IF EXISTS`、`INSERT ... VALUES` 合法；`profile VARCHAR` 存 JSON 文本，`json_extract_string("profile", '$.star') = '5'` 语义正确（DuckDB 对 JSON 字符串返回去引号文本、数字返回 `'5'`，缺失键返回 NULL → 过滤）。chapter 无自增列（显式 id，无影响）。
- **clickhouse**：`Int32/Float64/String` + `ENGINE = Memory` 合法；Memory 引擎不支持主键/UPDATE/DELETE——与 spec 跳过逻辑一致（见第四节）；`'null'` 种子是合法 JSON，`JSONExtractString` 对缺失键返回空串（`'' = '5'` 为假 → "missing key" 用例 0 行 ✓）。
- **oracle**：`NUMBER`/`VARCHAR2` + `GENERATED BY DEFAULT AS IDENTITY`（Oracle 23 Free 支持）合法；列名未加引号 → 存储为大写，与 `quote_ident_oracle` 大写输出匹配（commit 6b081a9/e5b3a99 系列已修齐，渲染验证 `"STATUS" = 1` / `"PROFILE"` ✓）。
- 种子 `dave O'Brien` 的 ANSI 转义（`''` 翻倍）在 oracle/postgres/duckdb 均正确。

### 发现的问题

- **F-3 [低] fixtures.lua:20-23 clickhouse schema 无主键且无注释说明**：Memory 引擎确实不支持主键，但 `users`/`likes` 在其他方言均有 PK——建议注释说明这是刻意的（upsert/update/delete 已跳过），避免后人误加 `PRIMARY KEY` 导致 CH DDL 报错。

## 三、.github/workflows/ci.yml — 新 job

### duckdb job

- **F-4 [中·残余风险] `DUCKDB_DIR=/opt/duckdb` 变量解析经实证成立，但完整编译链路未在本地闭环**：用 luarocks 3.9.2 探针实验（fake duckdb.h + stub lib）证实 `DUCKDB_DIR` → `DUCKDB_INCDIR=$DIR/include` 解析正确；再核对 luarocks 源码 `external_deps_subdirs.lib = "lib"`（unix），Linux 上 `DUCKDB_LIBDIR=$DIR/lib`，与 CI 布局 `/opt/duckdb/{include,lib}` 完全吻合 → `-I/opt/duckdb/include -L/opt/duckdb/lib -lduckdb` 成立。残余风险仅在 luasql-duckdb 2.8.0 的 `ls_duckdb.c` 与 duckdb 1.5.5 C API 的编译兼容性（本地 Windows 无法闭环编译验证），建议盯首次 CI 运行。
- **F-5 [低] duckdb wget 无超时/重试**：`wget -q` 单次拉取，GitHub 默认 6h 作业超时兜底；建议 `--timeout=60 --tries=3`。

### clickhouse job

- **F-6 [中] Lua 矩阵只覆盖 5.1/5.4，5.2/5.3 缺失**：sqlite/mysql/pg/duckdb 均全矩阵（5.1-5.4）；clickhouse adapter 是纯 Lua（luasocket+cjson），5.2/5.3 无理由跑不了。要么补齐，要么注释说明缘由。
- **F-7 [低] run 步骤 env 未传 `CLICKHOUSE_PASSWORD`**：靠 adapter 默认值 `"clickhouse"`（db.lua:387）与 service env 恰好一致。任一侧改动即静默认证失败。建议显式传入。
- **F-8 [通过] service 健康检查合理**：`clickhouse-client --password clickhouse --query 'SELECT 1'`（镜像自带 client），5s 间隔 × 20 重试；端口映射、Diagnose 步骤均无害。

### oracle job

- **F-9 [高] 安装步骤全部 best-effort，驱动装不上时作业照样绿**：`wget ... || echo`、`luarocks install luasql-oci8 ... || echo "build failed"`，随后 `busted` 无条件执行——luasql-oci8 缺失时所有 oracle spec `pending()`，作业显示绿色但 **oracle 覆盖静默为零**。建议：`set -euo pipefail`，或安装后加 `lua -e "assert(pcall(require,'luasql.oci8'))"` 硬校验失败即红。
- **F-10 [中] 缺 `zlib1g-dev`**：luasql-oci8 2.6.0-3 rockspec 链接 `libraries = { "z", "clntsh" }`，`-lz` 需要 libz.so（zlib1g-dev 提供）；ubuntu-latest 通常自带，但应显式安装以保稳健。
- **F-11 [低] `LD_LIBRARY_PATH` 硬编码 `instantclient_21_14`**：与 wget 版本 21.14 绑定；升级版本时需同步改。建议从 `IC_DIR` 动态导出。
- **F-12 [通过] 健康检查**：`healthcheck.sh` + start-period 60s + 30 重试，对 Oracle 23 Free 启动时长合理；`app/app/FREEPDB1` 与 adapter 默认一致。

### 通用

- **F-13 [低] rocks 未锁版本（上轮 P2-2 延续）**：`luarocks install luasql-duckdb` 取最新，当前 2.8.0-1 与 CI 布局假设吻合；未来版本若改外部依赖变量约定即碎。建议锁版本。
- **F-14 [低] `integration-servers` 每矩阵单元仍同时起 mysql+pg 两个容器（上轮 P2-1 延续）**：资源浪费，非本次新增。
- **F-15 [通过] oracle 仅 5.4 单版本**：合理（Instant Client 构建成本高），建议在 job name 或注释中说明是有意为之。

## 四、集成 spec 的方言条件跳过

### 结论：跳过逻辑正确且位置合理

- **UPDATE/DELETE 跳过 clickhouse**（roundtrip_spec.lua:79-85、99-105）：Memory 引擎确实无标准 UPDATE/DELETE，`pending()` 在 `before_each` 之后、执行之前触发——prepare（DDL/INSERT）照常跑且能通过，判定合理。
- **upsert 跳过**（upsert_spec.lua:24-31）：按 `dialect_mod.resolve(dialect).upsert == nil` 判定，clickhouse 与 oracle 均正确跳过（Lua 5.4 实测：clickhouse/oracle upsert=nil，duckdb=`ON CONFLICT DO UPDATE`）；duckdb 走 upsert 路径，渲染 `ON CONFLICT ("user_id") DO UPDATE SET "like_count" = excluded."like_count"`——`excluded` 小写引用与 DuckDB 语义一致 ✓。
- **F-16 [低] UPDATE/DELETE 用字面量 `conn.dialect == "clickhouse"` 判断而非方言配置**：未来新增无 UPDATE 方言时易漏。建议提取为 helpers 里的 `db.dialect_supports(conn, "update")`。
